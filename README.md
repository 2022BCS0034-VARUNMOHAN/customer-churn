# Customer Churn Prediction — MLOps Assignment II

## What This Project Does

A **telecom company** wants to predict which customers are likely to cancel their subscription (churn).

- **Stage 1** (Assignment 1): Used hand-written rules to predict churn
- **Stage 2** (This assignment): Replaced rules with a trained ML model + full MLOps infrastructure

## Running the Full Pipeline

Run these commands **in order** from your project root folder:

### Step 1 — Prepare data

Converts the raw CSV into a format the model understands:

```powershell
python scripts/prepare_data.py
```

This creates `data/processed_data.json`.

### Step 2 — Train the model

Trains the ML model and logs everything to MLflow:

```powershell
python scripts/train.py
```

This creates:

- `model.pkl` — the trained model
- `artifacts/` — evaluation plots and metrics
- `mlruns/` — MLflow experiment tracking data

### Step 3 — View MLflow experiments

```powershell
mlflow ui
```

Then open **http://localhost:5000** in your browser.

You'll see:

- Every training run with its parameters and metrics
- The trained model registered in the Model Registry
- Comparison between runs

### Step 4 — Run the API

```powershell
uvicorn app.main:app --reload
```

Then open **http://localhost:8000/docs** — this shows the interactive API documentation.

### Step 5 — Test the API

Open another terminal and run:

```powershell
# ML prediction
curl -X POST http://localhost:8000/predict-risk `
  -H "Content-Type: application/json" `
  -d '{
    "monthly_charges": 95.0,
    "previous_month_charges": 70.0,
    "contract_type": "Month-to-month",
    "tickets": [
      {"type": "complaint", "date": "2026-04-01T10:00:00", "description": "Terrible service"}
    ]
  }'
```

Expected response:

```json
{
  "risk": "HIGH",
  "engine": "ml",
  "churn_probability": 0.87,
  "features_used": { ... }
}
```

### Step 6 — Run tests

```powershell
pytest tests/ -v
```

### Step 7 — Check for data drift

```powershell
python scripts/monitor.py
```

Check the report:

```powershell
cat artifacts/monitoring/drift_summary.txt
```

### Step 8 — Automatic retraining

```powershell
# Check drift and retrain only if needed
python scripts/retrain.py

# Force retrain regardless
python scripts/retrain.py --force
```

## MLOps Components Explained

### DVC — Data Version Control

**Problem**: Git tracks code, not data. Which data trained model v3?

**Solution**: DVC tracks data files like Git tracks code.

```powershell
# Run the full pipeline (only re-runs changed stages)
dvc repro

# Compare metrics between runs
dvc metrics show
dvc metrics diff
```

### MLflow — Experiment Tracking

**Problem**: You train 10 models with different settings. Which one was best?

**Solution**: MLflow records every run automatically.

Every `python scripts/train.py` run saves:

- Which features were used
- What hyperparameters (settings) were used
- F1 score, ROC-AUC, Avg Precision
- The trained model itself

View at: http://localhost:5000 (after running `mlflow ui`)

### MLflow Model Registry

**Problem**: Which model is currently deployed in production?

**Solution**: The registry tracks model versions and their "stage":

| Stage      | Meaning                     |
| ---------- | --------------------------- |
| None       | Just trained, not reviewed  |
| Staging    | Ready for testing           |
| Production | Live, serving real users    |
| Archived   | Old version, no longer used |

When `train.py` runs, it automatically promotes the new model to `Staging`.

### Sklearn Pipeline

**Problem**: If training uses `StandardScaler` but inference doesn't → wrong predictions.

**Solution**: Pack scaler + model into ONE Pipeline object. Save and load as one unit.

```python
pipeline = Pipeline([
    ("scaler", StandardScaler()),
    ("classifier", RandomForestClassifier()),
])
# Save: joblib.dump(pipeline, "model.pkl")
# Load: pipeline = joblib.load("model.pkl")
# Predict: pipeline.predict(X)  ← scaler runs automatically!
```

### Drift Monitoring

**Problem**: Customer behaviour changes over time. The model silently becomes inaccurate.

**Solution**: Regularly compare the distribution of features seen at inference vs training.

We use **PSI (Population Stability Index)**:

- PSI < 0.1 → ✅ No significant change
- PSI 0.1–0.2 → ⚠️ Monitor
- PSI > 0.2 → 🚨 Retrain!

### CI/CD/CT Pipeline

Automated workflows that run on GitHub every time you push code:

- **CI**: Run tests automatically → catch bugs early
- **CD**: Build Docker image → deploy new version automatically
- **CT**: Check drift weekly → retrain model automatically if needed
